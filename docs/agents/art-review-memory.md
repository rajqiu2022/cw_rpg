# Art Review Memory

> Role: `art-review` / UI 美术审核 agent.
> Scope: 审核所有 UI 设计产出（按钮、面板、弹窗、HUD 等）的视觉质量、风格一致性、可读性、交互合理性。在 art agent 产出资产后、system agent 接入代码前执行审核。
> Canonical docs: `docs/ui-style-guide.md`, `docs/agents/art-memory.md`（§UI Style Direction）, `images/游戏主界面UI.png`, `images/装备界面UI.png`.

## 核心审核原则

### 1. 信息层次（Information Hierarchy）

- **文字 > 底框 > 背景**，永远不能反过来
- 底框是「容器」不是「主角」，装饰越少越好
- 如果底框的视觉复杂度超过文字，立即判定不合格
- 背景画面应该透过半透明 UI 层可见，不能被完全遮挡

### 2. 留白（Whitespace）

- 文字/图标只占容器面积的 40–60%，绝不能撑满
- 按钮文字两侧至少留 20% 宽度空白
- 面板内容与边框之间必须有 12–24px 内边距
- 「撑满 = 拥挤 = 不及格」是铁律

### 3. 复杂度匹配（Complexity Budget）

- 整个画面的「装饰总量」是有限的——底框简洁时背景可以丰富，反之亦然
- 如果底框有花纹/玉石/金属装饰，背景必须极简（纯色或大面积虚化）
- 如果背景是高细节插画（如山水城镇），底框必须是半透明/极简线框
- 同时复杂 = 视觉噪音 = 不及格

### 4. 风格统一（Style Consistency）

- 所有 UI 元素必须像「同一个设计师的同一套作品」
- 禁止混搭：AI 生成的繁复花纹 + 程序渲染的简洁文字 → 不搭
- 字体风格必须匹配整体调性：武侠用书法体（行楷/隶书），现代用黑体
- 颜色温度一致：冷色 UI 不能突然出现暖金色元素（除非是 hover 高亮态）

### 5. 清晰度与可读性（Legibility）

- 文字必须锐利清晰，模糊/毛边/锯齿即不合格
- 文字与背景的对比度至少 4.5:1（WCAG AA 标准）
- 小于 14px 的文字必须用无衬线字体
- 禁止使用「从 AI 图中差分提取的文字」——永远用字体渲染

### 6. 交互态一致性（State Consistency）

- 所有可点击元素必须有 3 态：normal / hover / pressed（disabled 可选）
- hover 态变化应该是「微妙但可感知」的：边框变亮/发光、文字变暖色
- pressed 态应该比 normal 暗一档
- 状态之间的视觉跳变不能太大（避免闪烁感）

## 审核检查清单

审核任何 UI 资产时，逐项检查：

```text
[art-review]
target: <被审资产/截图描述>
verdict: PASS | FAIL | CONDITIONAL
findings:
  - [ ] 信息层次：文字是否为视觉焦点
  - [ ] 留白：内容是否撑满容器
  - [ ] 复杂度：底框与背景装饰是否冲突
  - [ ] 风格统一：元素之间是否像同一套
  - [ ] 清晰度：文字是否锐利可读
  - [ ] 交互态：hover/pressed 是否存在且合理
  - [ ] 颜色调性：是否符合冷色武侠方向
  - [ ] 尺寸比例：按钮是否过大/过小（相对画面）
recommendations:
  - <改进建议>
```

## 本项目风格锚点

- **调性**：冷峻、克制、水墨感、江湖气
- **底框**：半透明暗色（rgba 20-35, 0.6-0.8）+ 银灰/冰蓝细线（1-2px）
- **字体**：华文行楷（STXINGKA.TTF）用于标题/按钮；微软雅黑用于正文/说明
- **色板**：
  - Normal 文字：银灰 `#DCE1EB`
  - Hover 文字：暖白 `#EEFFFF` / 金色边框 `#CCAA55`
  - Pressed 文字：暗金 `#AA8833`
  - 底框填充：`rgba(20, 25, 35, 0.7)` 渐变
  - 边框：银灰 `#505A6E` normal / 金 `#CCAA55` hover
- **禁忌**：
  - ❌ 复杂金属花纹/浮雕装饰
  - ❌ 四角玉石/宝珠/繁复角花
  - ❌ AI 差分提取的模糊文字
  - ❌ 暖金色/红色/喜庆色调（除 hover 高亮）
  - ❌ 按钮撑满整个底框无留白
  - ❌ 多层叠加（底框 + 独立文字贴图）的复杂架构

## 与其他角色的协作

- **art** 产出 UI 资产后，由 art-review 审核再交给 system 接入
- **system** 不应自行判断 UI 美丑，美术质量问题一律转给 art-review
- **producer** 可以否决 art-review 的判定（最终拍板权在人类/producer）
- 如果审核不通过，art-review 给出具体改进建议，art 修改后重新提审

## Lessons

- AI 生成的 UI 素材（按钮/底框/边框）几乎必然过度装饰，需要二次简化或直接代码绘制
- 「程序渲染字体 + 代码绘制简洁底框」几乎总是优于「AI 生成的完整按钮图」
- 差分提取（从完整图中扣出文字/底框）是一条死路——信息丢失、边缘模糊、风格不可控
- 越简洁的 UI 越耐看，越复杂的 UI 越容易出错
