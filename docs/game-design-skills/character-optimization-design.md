# 角色优化与缓解设计

> 来源：Game Design Skill for Claude Code - 基于《游戏设计的100个原理》

## 用途

设计角色创建系统、单位属性或基于数值的进阶系统时使用。

## 核心概念：Min/Maxing

玩家最小化不利特征、最大化有利特征的主导策略。

### 特征

- 特定技能/领域的高能力
- 降低整体灵活性
- 主导策略胜过均衡构建
- 常见于 RPG 和军事游戏

### 玩家视角

- **支持者**：符合规则、团队效率、优化满足感
- **反对者**：破坏社交契约、忽视叙事、破坏多人平衡

## 设计缓解策略

| # | 策略 | 描述 | 优点 | 缺点 |
|---|------|------|------|------|
| 1 | 预设值 | 限制自定义到预设选项 | 保证平衡 | 降低玩家自主性 |
| 2 | 随机生成 | Roguelike 风格 | 鼓励适应性 | 可能让玩家感到不公 |
| 3 | 互联属性 | 属性互相关联 | 维持深度 | 更复杂 |
| 4 | 主题强调 | 强调叙事和角色扮演 | 维持沉浸 | 可能无法阻止纯优化者 |

## 设计工作流

1. 定义专精与多功能的期望平衡
2. 选择缓解策略
3. 实现属性系统
4. 测试主导策略
5. 基于测试迭代
6. 监控上线后的新兴优化模式

## Min/Maxing 示例与缓解

| 游戏 | 问题/方法 | 缓解/结果 |
|------|-----------|-----------|
| D&D | 玩家 dump 魅力换力量 | 魅力影响更多机制 |
| Dark Souls | 复杂属性缩放系统 | Min/max 可行但多功能仍有效 |
| WoW | 早期允许极端 min/max | 后续强制平衡 |
| XCOM | 升级时随机属性成长 | 玩家适应士兵而非追求完美 |
| Civilization | 平衡基础单位 | 优化发生在游戏层面 |
| Multiclass | 多职业 cherry-picking | 递减回报、等级要求 |

## 相关设计陷阱

- **Powergaming** — 纯粹追求数值最优
- **Rule Lawyering** — 利用规则漏洞
- **Twinking** — 高级玩家赠送装备给新号

## 对本项目的应用

### 当前属性系统（CharacterStats）

```
筋骨 → 攻击、生命
机敏 → 速度、闪避
内劲 → 技能伤害、内力
悟性 → 经验加成、暴击
```

### 采用策略：互联属性 + 主题强调

- **互联属性**：每个属性影响多个战斗维度，避免"只堆攻击"成为唯一最优解
- **主题强调**：通过叙事和装备（如特定门派偏好特定属性）引导分配
- **装备限制**：高级装备要求多属性门槛（如需要筋骨≥8 且 机敏≥5）

### 平衡原则

- 全堆单属性时，应有明显短板（如纯力量角色面对快速敌人劣势明显）
- Boss 设计应针对不同 build 有不同弱点，鼓励多样化
