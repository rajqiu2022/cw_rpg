# 强化与反馈系统

> 来源：Game Design Skill for Claude Code - 基于《游戏设计的100个原理》

## 用途

设计奖励循环、惩罚机制和玩家行为引导系统。

## 核心概念

基于心理学的操作性条件反射（斯金纳箱），通过奖励和惩罚塑造玩家行为。

## 强化类型

| 类型 | 描述 | 效果 |
|------|------|------|
| 正强化 | 给予奖励 | 增加行为频率 |
| 负强化 | 移除负面状态 | 增加行为频率 |
| 正惩罚 | 施加负面后果 | 减少行为频率 |
| 负惩罚 | 移除奖励/资源 | 减少行为频率 |

## 奖励时间表

| 时间表 | 描述 | 效果 | 示例 |
|--------|------|------|------|
| 固定比率 | 每 N 次行为奖励 | 稳定但可预测 | 每杀 10 怪升级 |
| 可变比率 | 平均 N 次行为奖励 | 最强成瘾性 | 掉落概率 |
| 固定间隔 | 每 N 时间奖励 | 定期参与 | 每日登录奖励 |
| 可变间隔 | 平均 N 时间奖励 | 持续检查 | 随机事件 |

## 反馈循环

### 正反馈循环（富者愈富）

- 胜利 → 获得资源 → 更容易胜利
- 风险：滚雪球效应，弱者越来越弱
- 设计：需要上限或追赶机制

### 负反馈循环（平衡器）

- 领先者受阻 → 落后者追赶
- 风险：努力无回报感
- 设计：适度使用，不能完全抵消玩家努力

## 设计原则

1. **即时反馈** — 行为后立即给予反馈（< 1 秒）
2. **渐进奖励** — 早期奖励频繁，后期间隔增大
3. **多层奖励** — 短期（金币）+ 中期（装备）+ 长期（升级）
4. **惊喜感** — 可变奖励比固定奖励更有吸引力
5. **损失规避** — 人对失去的痛苦是获得快乐的 2 倍

## 对本项目的应用（战斗奖励/任务反馈）

### 战斗奖励设计

```
杀怪奖励层级：
├── 即时反馈（每次攻击）
│   └── 伤害数字 + 屏幕震动
├── 短期奖励（每场战斗）
│   ├── 金币（固定）
│   ├── 经验值（固定）
│   └── 物品掉落（可变比率 30-50%）
├── 中期奖励（完成任务）
│   ├── 任务奖励金币/经验
│   └── 关键装备（固定）
└── 长期奖励（章节结算）
    ├── 升级
    └── 新区域解锁
```

### 第一章奖励节奏

| 时间点 | 事件 | 奖励类型 |
|--------|------|----------|
| 1:30 | 击败流贼 | 金币+经验+任务完成（正强化三连） |
| 2:30 | 进入清风镇 | 新场景解锁（探索奖励） |
| 3:00 | 商店购买 | 装备提升（投资回报） |
| 4:00 | 废宅战斗 | 物品掉落（可变奖励） |
| 5:00 | 解救NPC | 声望+剧情推进（社交奖励） |
| 6:30 | 击败Boss | 大量金币+稀有装备+章节完成 |

### EventBus 反馈信号设计

```gdscript
# 需要在 UI 层响应这些信号提供视觉/音效反馈
EventBus.gold_changed      → 金币飘字 +N
EventBus.item_picked_up    → 物品获得提示
EventBus.quest_completed   → 任务完成弹窗 + 奖励列表
EventBus.level_up          → 升级特效（未实现）
EventBus.enemy_defeated    → 战利品掉落动画
```

### 损失规避应用

- 死亡不丢失物品/金币（避免惩罚过重）
- 但 Boss 战前自动提示"是否存档"（给玩家安全感）
- 失败后回到战斗前而非场景入口（减少重复感）
