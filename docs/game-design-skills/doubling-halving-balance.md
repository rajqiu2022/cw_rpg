# 加倍减半平衡方法

> 来源：Game Design Skill for Claude Code - 基于《游戏设计的100个原理》

## 用途

在原型和平衡调优阶段快速识别平衡问题。

## 核心概念

对核心变量做极端调整（2x 或 0.5x）而非微调，快速揭示变量是否有意义。

**关键洞察**：如果加倍或减半一个值而游戏体验没有明显变化，那说明这个变量当前不是平衡的关键因素。

## 执行步骤

1. **识别目标变量** — 移动选项、时间限制、资源分配、生命/伤害比
2. **选择调整方向** — 加倍（值过低）或减半（值过高）
3. **应用调整并测试**
4. **迭代直到发现影响** — 无显著变化则继续加倍/减半
5. **分析结果** — 找到有意义的范围后微调
6. **确定下一步行动**

## 示例工作流

```
问题：玩家初始生命 200，游戏太简单
→ 减半到 100 → 测试 → 仍然太简单
→ 减半到 50 → 测试 → 如果太难
→ 微调 50-100 之间
结果：2 次迭代找到有意义范围 vs 20+ 次微调
```

## 约束

- 仅内部工具（不用于发布版微调）
- 需要开发者知识
- 不适用于 A/B 测试
- 适用于快速原型阶段

## 何时使用

| 场景 | 使用 |
|------|------|
| 原型期快速验证 | ✅ |
| 数值完全未知 | ✅ |
| 玩家反馈"太简单/太难" | ✅ |
| 精细调优（已接近最终值） | ❌ |
| 对外发布前微调 | ❌ |

## 对本项目的应用（战斗数值平衡）

### 当前数值（.tres 文件）

```
冷孤云（玩家）:
  hp: 100, atk: 15, def: 8, spd: 12

流贼（thug_lone）:
  hp: 40, atk: 10, def: 3, spd: 8

赵无忌（boss_zhao_wuji）:
  hp: 150, atk: 22, def: 12, spd: 10
```

### 平衡验证检查清单

| 变量 | 当前值 | 减半测试 | 加倍测试 | 目标感觉 |
|------|--------|----------|----------|----------|
| 玩家 HP | 100 | 50（是否秒死？） | 200（是否无压力？） | 3-5 回合战斗 |
| 流贼 HP | 40 | 20（一击毙？） | 80（拖沓？） | 2-3 回合击杀 |
| Boss HP | 150 | 75（太快？） | 300（太拖？） | 8-12 回合 |
| 玩家 ATK | 15 | 8（打不动？） | 30（碾压？） | 每回合打掉敌人 20-30% HP |

### 快速平衡公式

```
理想战斗回合数 = 敌人HP / (玩家ATK - 敌人DEF)
理想生存回合数 = 玩家HP / (敌人ATK - 玩家DEF)

目标：生存回合数 > 战斗回合数 × 1.5（留有余量）
```

### 当前验算

```
vs 流贼: 40/(15-3) = 3.3 回合击杀 ✓
vs 流贼生存: 100/(10-8) = 50 回合 ✓（太安全，可以减少药品）

vs Boss: 150/(15-12) = 50 回合击杀 ✗ 太慢！
→ 需要技能打破 DEF 或 Boss DEF 需降低
→ 加倍法：ATK 加倍到 30 → 150/(30-12) = 8.3 回合 ✓
→ 说明需要技能系统提供额外伤害突破
```
