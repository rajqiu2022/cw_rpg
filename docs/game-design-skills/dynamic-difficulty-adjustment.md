# 动态难度调整（巴斯特原则）

> 来源：Game Design Skill for Claude Code - 基于《游戏设计的100个原理》

## 用途

基于玩家表现调整游戏难度以维持参与度。

## 核心概念

以 Buster Keaton（一只鹦鹉）命名，当主人受挫时降低游戏难度以延长游戏。

## 机制

1. 监控玩家行为检测挫败感
2. 多次失败时介入
3. 微妙地降低难度
4. 在后台执行调整
5. 将情绪从挫败转化为满足

## 监控指标

- `attempt_count` — 尝试次数
- `success_rate` — 成功率
- `time_spent` — 花费时间
- `rage_quit_indicators` — 怒退指标

## 调整策略

- 降低敌人生命/伤害（5-10%）
- 放宽操作时间窗口
- 减少敌人数量
- 提供额外资源
- 减慢敌人攻击节奏

## 检测阈值

- 3-5 次连续失败
- 增加的尝试间隔
- 快速重试无改善

## 示例

| 类型 | 检测 | 调整 | 结果 |
|------|------|------|------|
| Boss AI | 3次死亡 | Boss攻击慢10%+更明确预警 | 玩家学会模式 |
| 赛车 | 持续最后名/退出 | 橡皮筋效应 | 保持竞争力 |
| 平台跳跃 | 5次失败 | 稍宽平台+宽容判定 | 满足感完成 |
| 格斗 | 多回合失败 | AI降低攻击性 | 练习学习 |

## 约束

- 不能使游戏太简单
- 不适用竞技公平场景
- 保密调整（不通知玩家）
- 渐进应用

## 避免被检测

- 不要让调整明显
- 不要过度调整
- 不要中途改变机制
- 不要通知玩家

---

## 对本项目的应用（M6 章末 Boss）

- Boss 赵无忌战斗：监控玩家死亡次数
- 3 次失败后：Boss 伤害降低 10%，攻击前摇延长
- 5 次失败后：额外提供恢复药
- 实现为 `BattleController` 中的隐藏计数器，不影响存档
