## 1. 核查依据与边界

- [全景地图规范](../panorama-map-production-v2.md)：不得放大单张源图充当大地图；模块化局部地图；实际返回像素决定资源预算。
- [洛阳模块美术验收](../luoyang-modular-city-art-v2-20261003.md)：相机尺度一致、真实脚底、导航/Y深度；功能通过不能替代整体视觉验收。
- [洛阳街坊密度整改](luoyang-density-loading-20261024e.md)：同一成人标尺；真实街面围合；主街/次街/侧巷256/144/96px为该批设计目标，成人附门145～150px；不能把这些目标冒充两座新城已经实测通过。
- [洛阳资产差距审计](../luoyang-city-asset-gap-audit-20261016.md)：按有效角色像素量身高，屋檐投影与基座共同约束净距；不能放大普通小宅冒充大宅。
- 世界当前消费者为 `game/data/maps/world_map_jianghu_layout_v15.tres` 的 `compound_luoyang`，原生源1536×1024，逻辑显示720×480，专用完整城市微缩图。旧atlas文档中的拉伸建议、旧插值/超分实验不用于豁免当前质量问题。

本次新审计只测两个场景文件中直接引用Texture2D的静态Sprite2D，包含祖先scale与region。未展开外部实例、动画帧或shader UV；这些排除项在JSON逐项列出。不能称全游戏资产审计通过。

## 2. 确认的问题

| 赤岩关外两侧崖 | 放大2.2222/2.2207倍，主体高度3300逻辑px | 同类问题，不能只修城内镜头 |
| 赤岩关门核心/右翼 | 1.2 / 1.1819倍 | 一并列入像素预算；小于外围崖的严重程度 |

| 沙漠四个院墙组及井院 | 四组1.1985倍，井院1.0147倍；前后分层重复计入节点 | 也应纳入修正；不是独立新图数量 |
| 沙漠普通房屋 | 例如后排民居0.6897、转角楼0.6340、客栈0.6531、双铺0.7051 | 并非每栋楼都被放大。是否保留还需正常镜头核门高、风格与街坊密度 |

赤岩直接测得126个静态贴图节点，8个逻辑放大、其中7个在1080P/0.9镜头下仍放大；沙漠76个，18个逻辑放大、其中16个在该镜头下仍放大。**共202个节点/26个逻辑放大，节点数不等于独立资源数。**

屏幕密度公式：`屏幕像素/原生纹理像素 = 节点及祖先变换倍率 × Camera2D.zoom × 窗口拉伸倍率`。以上屏幕数值以1920×1080逻辑视口、窗口拉伸1计算；用户2750×1265截图不是本次重新捕获，不能冒称实测了该窗口的全部变换。

透明留白不增加主体像素；A128仅用于测可见包络，不能据此擦掉A1～127或拿包络代替碰撞。

## 3. 世界地图地标的偏差

当前实际来源：`game/build/three_towns_world_20261029j_system01/world_spec.json`。

- 赤岩只引用 `redrock_town_20261028a/core.png`，scale0.25。这是单个关门组件，没有城内街区与完整关镇轮廓。
- 沙漠引用 `dwelling.png`、`inn.png`、`enclosure_v2.png`，倍率0.16/0.14/0.28。整圈小墙与两栋大屋采用不同微缩比例，且缺完整城镇内容。
- 洛阳采用独立 `compound_luoyang`，有完整城廓、主建筑、次级屋群、明确前门和统一投影。

两处新地标的问题主要是**组成与微缩比例**，不是纹理被放大；不能通过提高分辨率或放大关门解决。M面板与mini地图的标点是另一个显示层，本次没有证据表明它们的标点定位失败，不改其坐标掩盖地标问题。

## 4. 返工方案与生产门槛

### 4.1 先做局部尺寸与接缝稿

保留已确认的六区功能和两城风格差异。先做含正式主角、成人门高、道路净宽、每块原生主体尺寸的装配稿；总览概念图不能作为贴图或通行证据。

赤岩第一样段取“北崖中段＋端部转角＋一处街巷”，沙漠第一样段取“城门＋两侧墙段＋转角＋邻近一栋民居”。正常跟随视角、接口近看、全景三种视图同时审查。样段合格后再扩展整圈，不以重复整城测试代替样段修正。

### 4.2 赤岩山体

- 将超过5千逻辑像素的北崖拆成短崖段、内/外转角、低坡收口；东西侧按同一等比例平行投影分别制作纵向段，不能旋转一张横崖冒充侧崖。
- 每段近景尺寸由原生主体有效像素决定；岩层高度、厚度、脚线、光向和接口带统一。长段必须依照接口装配，不能把独立山块散排后留缝。
- 当前2.2～2.6倍三方向大崖不再作为合格近景资源复用。旧图留作来源/风格参考。
- 岩脚实体、分层遮挡与现有三阶踏面同步；地形变更若侵入旧路，必须同步更新碰撞，不能仅缩小贴图留下旧巨型阻挡。

### 4.3 沙漠城廓、沙丘与院墙

- 退掉“整圈城廓放大5倍”的施工方法。新近景资源按城门、直墙、左右侧墙、转角塔、门接头分别生产，墙顶/墙根用明确接口连成真实围合。
- 整圈城廓旧图只作布局参考；禁止从其中裁出低清门窗再放大当新模块。
- 沙丘用不同短脊/坡脚段塑造边界，像素不足就缩短单段或新增合格模块，不对1640px主体扩成4000px。
- 院墙单独补足有效像素或调整分段；保留出入口与屋檐净距。
- 普通民居不机械全部重生，但必须复核正常镜头。保留足够楼型/高度差、连续主次街、院落与有功能的台地；不能用缩小房屋或重复同楼来掩饰空旷。

### 4.4 两张专用世界微缩城市

分别生产 `world_redrock_compound` 与 `world_desert_compound`，不与可步行城市墙体混用。

- 赤岩：红砂岩峡口关镇，主关门、沿阶密集屋群、侧后崖共同构成紧凑完整轮廓。
- 沙漠：浅土坯围城、平顶民居、棚市与少量井院枣椰，保持黄沙风格，不能改成红岩关或浓绿绿洲。
- 参照洛阳当前720×480逻辑包络校准投影和微缩层级；两镇可用更小包络，但须用主城旁对比图冻结尺寸，不能只在单图里觉得合适。
- 透明主体、前门脚线、body、depth、道路接点一起交付。保留赤岩World入口(2000,1050)、沙漠(650,1050)及既有ID；新轮廓与门脚若冲突，先调整资源设计，确需变更再同步完整合同。

### 4.5 本轮新增的像素准入要求

这是针对本次缺陷具体化的执行要求，不冒称旧文档已写出全部数值：

1. 静态近景模块节点及祖先合成倍率不得大于1；正常目标窗口下源纹理像素数至少覆盖最终显示像素。窗口放大需求须单独计入，不能只验scale。
2. 出图前记录“主体有效宽高→目标逻辑宽高→相机/窗口倍率”；出图后按实际返回图与alpha包络重算。请求尺寸和透明画布尺寸不能作为准入证明。
3. 先冻结接口尺寸再生图；新源像素不够时拆分模块，不用插值放大、锐化、加微纹理或拉远相机规避。
4. 不使用全景缩略图判断清晰度。必须在正常跟随镜头查看主角旁的山石、墙砖、门窗，及新旧模块接缝。
5. 街坊密度、成人比例、通路、台地高程、遮挡、World地标分别验收。清晰但拼缝/投影不合格仍不采用。
