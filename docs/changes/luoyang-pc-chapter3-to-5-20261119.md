## 修复内容

- 章节按钮改由正式转场负责校验入口。洛阳公开城门更新受影响的来源清单，为历史脚本保留可逐字节逆推的后继关系。府衙的剧情与人物来源也同步到现役版本。
- 府衙开场对白期间的任务刷新等待加载结束。主角站在案情榜交互区按空格时优先查案，附近访客的交谈范围不会截走这次输入。
- 府衙及街市通往旧城区的正式门户使用成对转场机制，校验原门、迁移落点，成功换图后才提交街区返程坐标。
- PC 主菜单与游戏内共用的读档面板在应用存档前，通过正式可玩地图的初次及末次来源校验，验证当前脚点和记住的回程脚点。区域自己的逻辑场景和地图坐标另由街区校验。图形客户端独立核对本例码头与城门两个落点约 18 秒，整次冷读还包括街区准备及实际进图。[图形端坐标校验](../../reports/luoyang_campaign_20261119_202631/desktop_savefeet.log) · [非法版本拒绝](../../reports/luoyang_campaign_20261119_202631/invalid_nav.log)

## 试玩边界

使用独立的 Godot 用户目录和槽 0。起点是构造的第三章结算前置，包含前两章完成标记、10 级主角、沈青禾和唐行舟、铁剑和 8 颗初始疗伤药。第三章结算之后，任务、证物、经验、金钱和战斗结果均由实际游戏产生。试玩通过方向键、空格、正式对白选项、战斗操作和界面按钮推进。修复期间多次从已写入的同一槽继续。诊断探针有独立前置，与表中的玩家路线分开记录。

前段使用 Windows Godot 的无窗口模式，追信使至第五章使用 Windows 图形客户端和 RTX 4080。此轮验证的是工程运行，Steam 导出包仍待验收。图形日志仍有三项既有启动来源拒绝与退出时的纹理释放错误。
