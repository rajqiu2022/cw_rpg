# 大地图与全景场景制作规范 V2

## 已确认的问题

- 当前 `world_map_jianghu` 的源图为 `1536x1024`，布局却声明为 `3072x2048`；这是运行时等比放大，不是大地图。
- 两张独立 AI 图直接左右并排不可用。即使提示词要求相同色调、道路和光照，模型也不会保留接缝像素，建筑尺度、地形和明暗会漂移。
- 把新生成的门、栅栏等物件覆盖在已经烘焙了同类物件的底图上同样不可用。底图原物件必须先被移除，或改用从一开始就不含该物件的场景底图。

## 接口能力实测（2026-07-30）

- `2048x1152` 的世界图请求实际返回 `1672x941`，不能把请求尺寸视为交付尺寸。
- 最后一次 `3072x1024` 超宽单图测试通过 dry-run，但 ALAPI 三次均返回 `422: 选定的 size 无效`，未产出图像。
- 结论：当前 ALAPI / `gpt-image-2` 通道不支持可用于本项目的超宽母图。停止超宽单图和独立双图拼接实验；世界旅行图使用已审核的原生单图，本地探索图进入模块化地形底图方案。

## 地图类型

| 类型 | 用途 | 尺寸与运行方式 |
| --- | --- | --- |
| 世界旅行图 | 城镇、门派、秘境之间的移动 | 低细节地形图，人物沿道路移动，地点为独立入口；不放置可检查建筑 |
| 局部探索图 | 村镇、山道、森林、门派 | 可走道路、NPC、宝箱、建筑、战斗与解谜；大于一个视口，可滚动 |

世界旅行图不承担村庄内部细节。进入地点后切换局部探索图，因此无需把所有城镇塞进一张超大场景。

## 可选方案

### A. 单张宽幅母图

请求并实测一张 `2048x1152` 或 `3072x1024` 的完整无文字地图。只有接口确认该尺寸可用、且人工验图通过，才采用。

- 优点：天然没有拼接缝。
- 风险：当前 ALAPI 已稳定产出的是 `1536x1024`，更高尺寸尚未实测；不能先假设可用。

### B. 真扩图 / 带重叠的两面板

适用于接口支持可靠图像编辑或 outpaint 时。左图是权威源图，右图必须以左图右侧 `384px` 真实像素作为不可改动的重叠区生成。

最终合成规则：

1. 两图均为原生 `1536x1024`，绝不缩放。
2. 右图左侧 `384px` 必须与左图右侧像素一致，不能靠提示词“看起来相似”。
3. 合成时保留一份权威重叠像素，最终成图为 `2688x1024`。
4. 接缝只能放在同一段平坦道路、草地或岩壁，不能穿过建筑、门、桥、围栏、NPC 位或交互物。
5. 先做原生合成图人工验收，再从该合成图标注碰撞、出口和物件。

当前 `gen_assets.py` 对参考图的 ALAPI 请求曾返回空 `400`，因此在该通道修复或增加真正的编辑端点之前，禁止用两张独立生成图冒充方案 B。

### C. 模块化局部地图（推荐）

局部探索图使用一张不含建筑和互动物的地形底图，加上正式独立 PNG：道路边缘、围栏、门框、屋体、树、石、箱子、火盆等。对象拥有独立的视觉、前景遮挡、脚底碰撞和互动层。

- 优点：不依赖 AI 拼接缝；地图可扩展到 `3x2` 或更多原生块；门框、栅栏、建筑可以正确遮挡角色。
- 要求：每一种重复物件从同一批正式图集切出；建筑不再同时烘焙在底图和对象层。
- 首批实践：林西村重做时先生成无村口、无建筑的地形底图，再摆放独立屋体、村口、围栏与竹林。

## 推荐落地顺序

1. 暂停把独立物件叠到现有林西完整底图上；当前只保留屋顶/门框脚底碰撞与原生底图显示。
2. 对世界旅行图先做一次高分辨率接口能力实验。若不支持，世界旅行图保持单张原生图，但把逻辑视口设为小于地图尺寸以获得有限滚动，不放大原图。
3. 第一张真正的大局部图选择“林西村主街到村外山道”，按方案 C 生成可拼接地形块和正式模块；先完成 `2x1` 的 `3072x1024` 原生组合。
4. 只有取得可锁定重叠像素的 outpaint 能力，才使用方案 B 扩展复杂自然地形。
5. 每次采用前必须验收：原生合成尺寸、接缝放大图、左右端滚动截图、出口可达、前景遮挡、屋顶不可走。

## 运行时约束

- `WalkableMapLayout.design_size` 必须等于最终合成图的真实像素尺寸；不得用于放大单张源图。
- `FieldWalkableController` 以最终合成图的原生尺寸建立世界；镜头滚动只移动容器，不缩放背景。
- 正向 `walkable_regions` 和脚底 blockers 均以最终合成图为唯一坐标基准。
- 角色遮挡采用 `ForegroundLayer` 的正式透明资源；若底图已烘焙同一物件，必须重做底图或不启用该前景资源。

## PC / 微信双档与分块流式加载（2026-09-09 已实施）

项目现在使用“唯一逻辑地图 + 两套光栅资源”，不再让清晰度档位改变玩法坐标：

- `SceneScript.streamed_background` 指向 `StreamedBackgroundSet`；`logical_size` 是导航、NPC、出口、任务物件唯一坐标空间。
- 微信/Web选择移动端块；Windows、macOS、Linux与桌面BSD选择PC块。没有分块资源的旧场景继续使用 `background_path`，可逐张迁移，不要求一次推倒全部地图。
- PC源图允许为逻辑图的2倍或更高；每块记录 `draw_scale`，显示时还原到同一逻辑尺寸。高分辨率只增加纹理细节，不会移动道路、碰撞或传送点。
- 相邻块从同一张审核通过的母图裁切，并保留12px逻辑重叠。严禁把独立生成的图片直接当相邻块。
- 首屏相交块同步预热，避免Loading结束后黑块；移动后的新块使用线程加载，远离视口的块释放。Web端不依赖线程加载，边缘块使用兼容同步路径。
- M键地图使用移动端整图预览；探索场景本身不再预先加载整张背景，因此分块不会被隐藏的整图副本抵消。
- 微信staging会显式排除`art/background_chunks/**/desktop/`；移动端块仍按章节/公共包规则归属。

首个正式样板是江湖大地图v8：逻辑/微信档为2304×1536，PC档由本地Real-ESRGAN生成4608×3072源图，两档各裁成15块。生成与验收命令：

```powershell
python scripts/upscale_world_map_v8_pc.py
python scripts/build_streamed_background_variants.py --mobile game/art/backgrounds/region_masters_v2/bg_world_map_jianghu_v8_2304.png --desktop assets/raw/scene_background/later_regions_codex_builtin_v2/bg_world_map_jianghu_v8_pc_4608.png --output game/art/background_chunks/world_map_jianghu_v8 --logical-width 2304 --logical-height 1536 --chunk-size 512 --overlap 12
python scripts/validate_streamed_background_variants.py --manifest game/art/background_chunks/world_map_jianghu_v8/manifest.json --mobile-source game/art/backgrounds/region_masters_v2/bg_world_map_jianghu_v8_2304.png --desktop-source assets/raw/scene_background/later_regions_codex_builtin_v2/bg_world_map_jianghu_v8_pc_4608.png
```

后续洛阳、门派等大型场景必须先完成布局迁移，再接入双档资源；不得因为已有2304×1536候选图就跳过导航、遮挡、任务入口与左右端滚动验收。
