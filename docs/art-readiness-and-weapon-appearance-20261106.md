# 内容铺量前资源盘点与名器外显方案

日期：2026-11-06。状态：静态盘点与制作提案；不是新资源已制作、外显已接入或全场景美术验收。

结论：现有资源能支撑继续制作小规模内容，但不能据文件总量判断已经适合大量铺城镇、装备和武学。优先缺口是顶级内容的独立辨识度、地图组件的成套接口、交互物件状态，以及按具体装备切换外观的完整链路。武器挂点不要求转成3D；本项目优先验证分层2D方案。

本次图库还有“家具与物件”33、“互动与调查物件”16、“动态氛围物件”3条记录。这些是分组记录，不是完整状态套件数量。后续最需要的是以下成套补充：

1. **结构接口件**：墙的正/侧/转角/收口，坡岸正/侧/阶口，桥头接岸，台面与挡土立面。每件登记可连接的方向和高度；先通过一段真实拼接再批量扩。

3. **交互状态**：箱子关/开/空、门关/开、矿脉完整/耗尽、药草可采/已采、机关待机/触发。按业务需要配状态，不强制所有摆件都有动画。
4. **环境动态**：水流、轻烟、火盆、布幡等克制循环。场景建筑保持不透明；遮挡采用人物半透明影像，武器和光效也须遵守同一遮挡规则。
5. **三种用途分开交付**：背包图标、放在地图中的实体、小地图/World符号。不能把UI图标直接放大摆进场景。

地图现存问题依据 [S01–S07质量标准](scene-art-quality-standard.md) 与 [缺陷册](scene-art-defect-register.md)：CITY-01密度/地域关系、LAN-02坡岸重复、HUA-01近岩及SCALE-01残余尚不能按“PNG够多”关闭。本次不冒充逐地图正常镜头审图。

建议扩量门槛：每个风格先做一段完整可走的代表街坊，至少具有明显大小差异的主/次建筑、用途明确的物件组、真实出入口、可读的高差连接、正确mini与遮挡；通过后复用它的尺度和接口合同。

## 4. 当前武器外显链路

地图主角见 `game/scripts/field/player.gd`：单个Sprite2D，按 `weapon_style + direction + idle/walk` 取整套人物贴图，路径根为 `game/art/characters/weapon_variants/lengguyun/v7_idle_stable/`；五类是sword/dao/staff/palm/hidden。idle4帧，walk8帧。

`game/scripts/field/field_walkable_controller.gd` 读取装备的 `weapon_type`，传入 `set_weapon_style()`，没有传入具体名器外观ID。

战斗见 `game/scripts/battle/battle_controller.gd`：同样按武器类型选主角整图；剑/刀用 `weapon_variants_v4`，其他用v3；ready/move/attack/hit/defeat各4帧。换武器时会刷新角色，但同类型两把剑仍选择同一套图。

`game/scripts/domain/equipment.gd` 的 `special_effect_*` 是破甲/中毒等战斗规则，不是视觉附魔。当前读取的装备类和两条玩家渲染链没有具体武器的appearance/enchant绑定。不能把七星剑35%破甲数值与剑上的常驻星光当成同一系统。

当前已存在橙招演出层 `game/scripts/battle/legendary_skill_cinematic.gd`，盘龙十七式有专属全屏帧。它可保留，不能因此认为所有名器都有常驻附魔；反过来也不应声称高级演出完全没做。

## 5. 是否需要3D：不需要，推荐先做分层2D验证

Godot已有2D节点挂载、精灵帧动画和2D骨骼。Marker2D本质是带编辑提示的Node2D，不会自动追踪贴图里的手；手的位置必须由我们逐帧标注/驱动。[Marker2D](https://docs.godotengine.org/en/4.6/classes/class_marker2d.html)、[精灵动画](https://docs.godotengine.org/en/4.6/tutorials/2d/2d_sprite_animation.html)、[2D骨骼](https://docs.godotengine.org/en/4.6/tutorials/animation/2d_skeletons.html)。以下成本与适配评价是结合本项目消费者作出的设计判断。

| 方案 | 美术工作 | 优点与边界 | 建议 |
|---|---|---|---|
| 每把名器一套完整主角图 | 每种武器重出人物全部相关动作/方向 | 接现有管线容易，人物比例/衣纹/脸易漂移；加服装后组合数继续增长 | 仅保留给极少数难拆的特殊招式或临时样例 |
| 无武器身体帧＋独立武器层＋逐帧挂点 | 每种持械姿势族一套身体，名器提供透视武器图/必要替换帧和FX | 保留2D画风与现有移动/战斗规则；需要手部前后遮罩和逐帧对齐 | **首选，先剑/刀两套验证** |
| Skeleton2D分件角色 | 身体、头发、衣摆、手臂等拆件、绑定与各朝向设计 | 武器挂骨方便；多方向与透视仍要做，可能出现纸片变形 | 可另做样例比较，不是挂点必需前提 |
| 3D模型骨骼→离线渲染2D帧 | 模型/拓扑/材质/绑定/动作/固定相机灯光 | 换装、多武器动作一致性好；前期成本高，仍需风格和帧输出规范 | 若未来大量服装/多主角可长期考虑 |
| 游戏内实时3D角色 | 以上＋2D场景中3D角色渲染/阴影/深度接合 | 自由换装强，但与现有遮挡、地形、像素密度衔接工程更多 | 不为附魔光效单独迁移项目 |

整图方案的最低数量例子：按现有地图4方向×(idle4＋walk8)=48帧，加战斗5动作×4帧=20帧，单武器约68个角色帧；20把就是1360个角色帧，尚未计新招式/服装。这是按现有约定估算，不是工作日或性能估算。分层方案仍要校对相应武器姿态，但不必反复重画脸、身体和衣服。

现有图中的刀剑已烘焙在人像上，**只加一个挂点会出现旧武器＋新武器重叠**。要准备无武器、但保持握持姿势的底稿和前景手指层；不能把“空手掌法人物”直接当持剑姿态。大刀/双手棍需要各自握法，不能靠同一手腕位置硬套。

最新主角原生高清四向/全部动作尚未正式齐套。此时先锁分层规范，可避免先批量完成绑定武器的人物，再拆开重做。

### 建议最小外观合同（尚未实现）

用独立外观注册表按 `item_id` 映射，不先改变装备数值或存档格式：

```text
item_id → appearance_id → pose_family
                       → field_visual / battle_visual
                       → grip_and_tip_tracks
                       → enchant_idle / swing_trail / impact_visual
```

每个动作/方向/帧记录：脚锚、握点、剑尖点、局部角度、武器透视替换帧、在身前/身后、手指前景层。身体/武器/FX共享一个动画时钟与坐标系；急停、转向、换武器时一起切帧。挂点解决位置，不自动解决透视缩短和双手握持。

推荐可组合层次：背后光效/武器 → 身体 → 前方武器 → 握持手指 → 前方局部光效。按姿态切前后层，不把整把武器永久放在主角前面。地图与战斗使用不同视觉适配器，但共享名器身份/配色和主题。

现有 `BuildingOverlapGhost` 只复制一个人物Sprite。分层后必须同步合成人物、武器与允许显示的克制FX影像，继承现有半透明规则；不得恢复建筑挖洞/透明，也不得让发光剑穿过整栋房子。高清适配器、World缩放、内外景脚点、战斗换装刷新都属于接线验收项。

## 6. 名器光效设计

光效分成4种用途：持有时低强度循环、出招时轨迹、命中时短反馈、传奇招式单独演出。品质越高不等于光圈越大；城市场景保持可读性。

| 名器 | 武器本体 | 常驻与动作表现提案 | 数据边界 |
|---|---|---|---|
| 七星龙泉剑 | 保留当前七星嵌点、细长剑身和剑格特色 | 剑脊七点依次微亮、低频星线；出剑短星轨，命中收束星芒；不持续罩住人物 | 已有 `seven_star_sword`，不改破甲属性 |
| 烬河断岳刀 | 按当前专属图标统一刀形与纹路 | 可考虑刃缝余烬、短促火星及沉重斩痕，与星剑形成材质和节奏差异 | 已有 `jinhe_duanyue_blade`；视觉提案不是新增伤害规则 |
| 用户举例的雪饮刀 | 若制作，需独立刀形与冷冽材质，不能只给普通刀套蓝色 | 薄冰刃光/少量冷雾、出刀霜弧、命中短冰晶；与七星剑区别在形态和运动 | 本轮equipment数据未检出“雪饮”定义；可做命名待定视觉样例，不擅自新增装备与投放 |

首选局部透明/加色贴图配必要的少量粒子，利用握点和剑尖轨迹定位；无需靠全屏Bloom达到“附魔感”。项目配置是Godot4.6 GL Compatibility，先保现有渲染器。CanvasItemMaterial支持加色；4.6 Compatibility的Glow实现与Forward+/Mobile不同，HDR2D路线也不能照搬，具体设备效果需样例验证。[材质混合](https://docs.godotengine.org/en/4.6/classes/class_canvasitemmaterial.html)、[Glow与2D设置](https://docs.godotengine.org/en/4.6/tutorials/3d/environment_and_post_processing.html#glow)。

预算建议先作为样例目标：地图只给近处可见角色启用常驻FX，离屏停发射，World缩略状态降级；限制同屏效果数量和透明覆盖面积，不给每把白装建常驻粒子。记录开启/关闭前后的帧耗时、draw calls、显存及加载差，不预先承诺无性能影响。当前加载仍有已知长帧，更不宜全库预载所有名器帧。

## 7. 落地顺序与验收

1. **P0 数据缺口**：处理 `wolf_rending_bite` 未登记（先确定合适的撕咬效果，不随意映射成剑光）；补4件橙装、15个橙技的专属图设计。当前显式路径无缺失，应把“兜底/共用”当美术欠账而非坏文件。
2. **P0 外显样板**：七星龙泉剑＋已有烬河断岳刀，先原生无武器握持底稿/手指层/武器透视样本，在独立预览完成方向、行走及攻击的验证，再决定是否扩所有动作。需要满足相同持姿可换第二把武器，才能证明不是又做两套绑定整图。
3. **P1 成套图标**：审查其余10件橙装，保留合格设计；补高级秘籍实体/内功按钮的对应关系，再按近期实际投放补26件其他装备和16件物品兜底。秘籍新增与可获取性由玩法设计确定。
4. **P1 地图生产包**：选择下一批真正要做的区域，先1套结构接口＋1组行业物件＋1个完整可走样板；图库登记原图/工程图/用途/消费者和状态。避免全风格同时补同一批杂物。
5. **P2 扩量**：样板通过后，按装备/关卡需求批量生产；若服装/主角数量显著增长，再用同一剑刀样例比较离线3D渲染的成本与风格一致性。

外显样板必须验：四向待机/行走，战斗ready/move/attack/hit/defeat，急停转向/换装，手不脱柄、剑不穿掌、脚锚不动、旧武器不残留；人物半透明遮挡、正常城市光照/浅色沙地/深色室内，以及功能不受FX影响。特效不遮HUD、入口箭头或目标，武器更换后旧FX立即结束。功能结果与正常镜头美术接受分别记录。

图标样板必须验：去品质框仍有身份、同类顶级物件可辨、64/96/128px可读、透明边无黑白底、详情展示不过度放大。地图样板沿S01–S07，入口/道路/高差/碰撞/mini同源；只验本次改变的范围，不重复历史全城旅行矩阵。

本报告完成的是静态审计与可执行制作方案。新图、外显原型、映射修复和全动作高清均未在本轮实施。
