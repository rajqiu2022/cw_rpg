# 分层场景制作合同 · 2026-09-29

## 玩家反馈与本次落地

林西村中心的旧水井烘焙在整张底图里，另叠一块前景裁剪图。截图里角色的可见脚底已经在井前，井却仍盖住角色。根因是旧前景比较角色节点原点（身躯锚点），而角色渲染排序比较贴图脚底；两个 Y 坐标不一致。此次运行时把旧 `y_sort` 前景的比较坐标统一成角色真实渲染脚底，门楼淡化触发区仍保持原有场景坐标。

林西村中心作为独立物件样板：底图改为无井地面 `bg_linxi_village_center_clean_well_v4.png`；透明井 `linxi_center_well_depth_prop_v1.png` 通过 `visual_objects` 摆放，图像、井座碰撞、脚底纵深线写在同一条记录里。角色出生排序移到外观缩放/脚底锚点确定之后。实机双侧截图在 `game/screenshots/linxi_well_depth_20260929/`：井后 `actor z=58 < well z=69`，井前 `actor z=84 > well z=69`。井座不可通行。

这只是**一口井的实装样板和通用脚底坐标修复**，不是全部旧场景改造完毕。全场景保守审计仍有 49 个双侧可走、未成对遮挡的候选，需要逐图判断；复杂建筑不能仅凭 Y 排序，还须门洞/檐下分区或像素遮挡蒙版。

## 后续大地图与场景的资源合同

1. 底座只承载连续地面、水体、地貌和道路。可走蒙版与地貌/路网取自同一逻辑源，水、悬崖、城内缩影不能被道路层重新涂通。
2. 井、灯柱、树、桥栏、摊位、房屋、城池地标等有体积的元素尽量作为透明独立物件摆放。每个物件同时登记透明图、世界位置、视觉脚底线、脚底阻挡，以及必要的交互/入口站位；不可只有图片没有碰撞或只有碰撞没有遮挡。
3. 角色和普通物件在同一纵深阶梯比较**真实脚底 Y**；复杂门楼用独立实体像素蒙版，只在角色进入门楼底层且发生实体重叠时半透明。楼梯、门洞外的空地不淡化。
4. 城市地图使用等比例 2.5D 局部可玩场景，不把带消失点的远眺图当成玩家可行走底图。
5. 外部授权资源必须登记原始链接、作者、素材级许可证、获取日期、允许的修改/商用范围及所做加工；无法核验的候选不可入正式游戏。自生成物件也要记生成批次和源图，不能误标为 CC0。生成图与授权素材可混合，但视觉、投影和比例需按实机截图验收。

## 验收门槛

- 每个可走区域抽测：地面正例，水/墙/物件脚底负例，以及所有入口从道路可达。
- 每个双侧可接近物件抽测：角色在物件后、前各一帧，比较脚底纵深并检查可见遮挡；出生点不能落在物件上。
- 整张新大地图需连续截图审查道路、岸线、桥、九区边界和城池比例。v13 候选当前严格视觉门禁未通过，正式运行继续保留 v12，不因逻辑测试通过就切图。
