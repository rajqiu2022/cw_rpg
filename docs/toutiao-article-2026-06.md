# 一个人+AI，我用 Godot 4 + GPT-Image-2 做了一款武侠 RPG

> 2026年6月，我用 AI 辅助游戏开发的第 4 个月。从零到可玩的武侠 RPG 第一章，经历了 7 个里程碑、64 个任务、数百次 UI 迭代。这篇文章是一个真实记录——不吹不黑，讲清楚 AI 到底帮了什么、帮不了什么。

---

## 项目是什么

《云影侠传》——一款致敬经典《风云之天下会》的 2.5D 武侠 AVG-RPG。主角冷孤云从林西村下山，卷入武林大派弟子接连被害的奇案，在古峰、华山、凌月、茗雾、武当五派中拜师学艺，结识三位红颜知己，最终揭开茗雾山庄千年阴谋。

**技术栈**：Godot 4 GDScript + Python 资产管线 + ALAPI (gpt-image-2) + ChatGPT/Claude AI 辅助编程。

完整代码已在 GitHub 开源：[github.com/rajqiu2022/cw_rpg](https://github.com/rajqiu2022/cw_rpg)

## 4 个月干了什么

### 基础骨架（M1-M5）

- **数据驱动战斗系统**：敌人/技能/装备全部 `.tres` 资源文件定义，新增敌人 = 加文件不改代码
- **探索场景 + 互动热点 + 对话系统**：AVG 式点击场景，支持分支对话、选项、任务触发
- **背包 + 装备 + 任务面板**：6 装备槽、36 格背包、中文分类筛选、8 章 64 个任务卷宗
- **多场景跳转 + NPC 对话链 + 商店买卖**
- **存档系统 v4**：5 槽位，持久化背包/装备/任务/flag

### 战斗系统升级（M6，2026 年 6 月）

- 5 种状态异常：中毒/虚弱/爆发/眩晕/冰冻
- 5 层决策树 AI（保命→压制→消耗→狂暴→默认），替代原来的 3 行启发式
- 伤害公式独立为 `BattleFormula.gd`，方便测试和调优
- 技能互补系统：内功+外功配合触发额外效果（如凌月·寒霜针 + 月华引 = 中毒+50%）
- 35 个敌人、31 个技能，7 个章末 Boss
- 章节结算画面 + Boss 战特殊路由

### 音频系统（M6）

- AudioManager 全局音频管理：BGM 淡入淡出 + 8 个 SFX 池化播放
- 场景切换自动换 BGM（读 SceneScript.bgm_path）
- 存档持久化音量设置

## AI 到底怎么帮的

### 1. 美术出图：从占位到可用，走了很多弯路

我们用 ALAPI (v3.alapi.cn) 的 gpt-image-2 接口生成 UI 面板和按钮贴图。

**装备/背包面板**是第一个成功的案例——prompt 里加了 `identity_anchor` 锚定"寒山玄铁冷色风格"，引用了已有的优秀设计稿作为 `reference_images`。出来的效果很统一：深墨蓝玄铁底、冷钢蓝边框、云纹角花装饰、港漫厚涂质感。

**任务面板的坑**：最早的 prompt 模板把十几个控件挤在一张 1024x1024 的绿幕拼图里生成，每个控件只有几十像素，细节全毁。后来改成**单组件高分率生成**——每个控件一张图，加 `identity_anchor` + `reference_images` 锁定风格。底图用 1536x1024 宽幅比例。效果立刻好了一个档次。

**最大的教训**：放一个"参考图"到 prompt 里，比写一百个形容词管用。AI 图像模型对图片的感知远强于对文字的理解。

### 2. 写代码：7 个里程碑全靠 AI 协作

我用 Claude/OpenAI Codex 配合写 GDScript。典型的协作流程：

1. 我描述需求（"给战斗系统加眩晕和冰冻状态，晕了跳过回合，冻了跳过+挨打更疼"）
2. AI 读现有代码，设计数据模型和逻辑
3. 生成代码，我 review + 跑游戏验证
4. AI 根据反馈修改

**真实效率**：M6 整个战斗系统升级——包括 3 个新 domain 类、5 种状态异常、5 层 AI 决策树、7 个 Boss 配置——大约 3 小时完成。如果纯手写，保守估计要 2-3 天。

### 3. 任务/剧情设计：AI 给了 34 个支线

我让 AI 按 8 章分别设计支线任务，要求融入中国文化元素——结果它给了 34 个：围棋残局（范西屏大国手）、古琴遗谱（《广陵散》）、龙门石窟谜踪、白马寺铜钟共鸣、洛阳纸贵（左思《三都赋》）、牡丹诗会、丹房试药……每个任务都有完整的前置/进行中/完成三态描述、触发条件、奖励配置。

## AI 帮不了什么（实话）

### 1. UI 对接是最大的时间黑洞

我们花了大量时间在 UI 控件的尺寸、位置、z-index 层叠上。AI 看不到运行时截图，只能盲猜——它改了 .tscn 和 .gd 文件，但不知道编辑器里实际效果怎样。

**解决方案**：参考了开源项目 [godogen](https://github.com/htdt/godogen) 的"截图驱动反馈"思路——用 Godot `--headless` + `--write-movie` 自动截图，AI 对比图像差异再改代码。但这个流程对 GDScript 2D 项目适配还不完善。

### 2. 进度回退很常见

GDScript 严格模式 + Variant 类型推断的坑多得令人崩溃。经常是改完 300 行代码，Godot 报 5 个 Parser Error，一个一个修回来。`var x := func_call()` 跟 `var x: Type = func_call()` 的差异能让 AI 出错十几次。

### 3. 风格一致性靠人工把关

虽然 prompt 里加了 identity_anchor，但不同批次出的图在色调、细节密度上还是有差异。最后是靠人肉眼比较，挑出最好的一张当 reference，下一轮 prompt 引用它，慢慢收敛。

## 最后的想法

这 4 个月最大的收获不是做出了一个游戏，而是找到了一套**"人定方向、AI 执行、人做 QA"** 的协作模式。AI 非常擅长：
- 生成大量结构化内容（任务、技能、敌人数据）
- 写重复性的 UI 布局代码
- 设计变体和分支（34 个支线任务、8 章任务树）

但它非常不擅长：
- 理解"好看"（需要反复贴参考图）
- 调试 Godot 的类型系统和语法
- 独立完成端到端的视觉开发

如果你也在用 AI 做游戏，我的建议很简单：**让 AI 当你的代码手和素材工，但审美、架构决策、最终验收，必须你自己来。**
