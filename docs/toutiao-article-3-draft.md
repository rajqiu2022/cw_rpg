# 我用Claude Code+DeepSeek做武侠RPG：《云影侠传》开发实录（3）

前两篇讲了主菜单场景和主角 sprite 动画的 AI 生成过程。这回搞背包界面——不是画一张图，而是把整组 UI 素材体系化地生成出来。

## 设计稿 vs 实际素材：概念图的陷阱

最开始有一张背包界面的设计稿，画面里面板、按钮、道具图标一应俱全，很好看。但设计稿的问题是：**它是"示意图"，不是"素材"**。

你想把上面的按钮抠下来当 TextureButton 用？抠出来的是 87×31 的异形块，而 Godot 需要的是标准尺寸的独立 PNG。设计稿上已经画了道具图标，但实际游戏里道具是动态加载的，你不能让所有格子都显示同一把剑。

所以第一步：扔掉设计稿。从零生成**干净的底图面板**。

## 四种素材，一套风格锚点

背包界面需要四类素材：

| 素材 | 说明 | 数量 |
|------|------|------|
| 底图 panel_bg | 1280×720 暗色面板，**内部完全空白** | 1 |
| Tab 按钮 | 全部/消耗/装备/剧情/材料，每种三态 | 15 |
| 功能按钮 | 使用/装备/丢弃/关闭，每种三态 | 12 |
| 道具格子 | 默认/选中/空 | 3 |

全部走 ALAPI 的 gpt-image-2 生成，prompt 统一挂 `STYLE` 锚点：

> Deep navy black base, dark gold accents, frosted dark glass, dark steel borders with warm gold edge, Chinese cloud scroll motifs.

风格统一是这条管线的核心价值——**一次写好 STYLE 锚点，所有 prompt 引用它**，底图的边框纹理、tab 的材质手感、按钮的光泽度自然就串起来了。

## 一个关键决策：不在 prompt 里写中文

gpt-image-2 生成中文文字的能力极不稳定——经常出现乱码、错字、笔画残缺。与其赌模型能写出对的"装备"二字，不如一步到位：

1. prompt 明确写：**"No text, no characters — just the decorative frame"**
2. 拿到纯装饰底框后，用 PIL（Python 图像库）加载系统宋体/黑体，精确居中写上中文
3. 文字位置像素级可控，字体也不会被 AI 画变形

这套"AI 出底框 + PIL 加中文"的流水线在前面几篇里反复验证过，现在完全成熟了。

## 三态效果怎么搞

按钮需要 normal（默认）、hover（鼠标移上）、pressed（按下）三种状态。

我的做法：

- **Normal**：AI 生成的原始底框 + PIL 加普通颜色文字
- **Selected/Hover**：PIL 在底框上叠加一层半透明青色，外围加一圈高斯模糊发光边框，文字换成亮色
- **Pressed**：PIL 把整体亮度降到 65%，加一层深色调叠加

三态变体**不额外调 API**，一张底框吃遍。GaussianBlur 的发光效果虽然简单，但在暗色底上非常明显——比很多商业游戏的三态切换还清晰。

## 结果和成本

四类素材共 9 次 API 调用（底图 1 + tab 底 1 + 按钮底 1 + 格子 3 = 6 次 ALAPI），剩下 25 个变体文件全部由 PIL 生成。

比逐帧 sprite 那篇的 ¥30+ 烧钱经历强太多了——**UI 素材是 AI 生图最能稳定输出的领域**。不像角色动画有帧间一致性问题，UI 元素只要风格锚点对，一次就过。
