# 战斗数值审计与重整建议 · 2026-09-10

状态：本文保留**调整前调研与诊断基线**，下文旧值不要视为当前运行值。用户批准后第一轮已实施，见[实现记录](combat-balance-implementation-v1-20260910.md)与[真实行动实测](ch1-balance-playtest-20260910.md)。以下目标是本项目的候选验收预算，不是行业通用标准；未实测部分仍不视为最终平衡。

## 1. 结论

当前问题不是单纯“武器攻击不够高”或“怪物血太少”，而是旧敌人攻防、新角色派生属性、强化装备、零耗蓝技能、残血衰减和永久奖励没有统一校准。应先修正成长效果与测试模型，再按真实游戏路线平衡。开放世界越级获得好装备/队友后明显变强是目标，不应通过全地图跟随玩家升级抵消收益。

### 2.1 零耗蓝使普通攻击失去取舍

- `game/data/skills/linxi_basic_sword_one.tres`：固定10 + 100%攻击，内力消耗0；二式固定18 + 115%攻击，消耗5。扣蓝路径本身存在，并非界面不刷新。
- 普通攻击固定2 + 100%攻击，命中85%；一式默认命中90%。持剑且一式可用时，它同时有更高伤害、命中和同样零成本，缺少使用普攻的资源理由。
- 华山一剑、开山一刀、凌月点星棍、茗雾扫风、太极拳·揽雀尾等攻击资源也配置0内力。需按“玩家主动攻击/敌人专用/被动心法/防御”分别审计，不能把所有0内力都当成错误。例如被动心法没有释放成本是合理的，敌人重斩为0内力也不等于扣蓝故障。
- 切磋结算会恢复入场生命/内力快照；“战后内力没少”和“一式战斗中没有消耗”是两件事，须分别测试。

### 2.2 减法防御出现过早不破防

`game/scripts/domain/battle_formula.gd`：先计算固定伤害与攻击系数、浮动和暴击，再直接减防御，最低1点；之后再处理伤势与其他乘区。

主角新局：184生命、84内力、攻击24、防御22。配置林西铁剑+麻布衫+草鞋的早期参考套装：攻击40、防御23。此参考套是审计构造，并非宣称新局自动全套装备。

### 2.3 残血衰减放大先手优势

同一公式对所有角色应用：生命低于70%/50%/30%/10%时，输出乘0.85/0.65/0.45/0.25。它既让玩家被压低血后难以反击，也使敌人挨几刀后丧失威胁。建议对比“取消全局衰减”和“仅明确受伤状态影响输出”两个版本，不再把巨大惩罚隐含在生命条里。此处只是候选变更，尚未删除规则。

### 2.4 成长效果断链：先于调参处理

- 一式的 `school="generic"`，二式为 `linxi`。林西铁剑有林西专属系数12和剑系系数6；实测一式只获6、最终106%，二式获18、最终133%。需要修正归属并验证所有“提升对应武功”的描述与运行效果一致。
- 林西酒通过 `Inventory.use_item` 直接增加派生生命/内力上限，没有独立永久加成源；`CharacterStats.refresh_derived_stats` 重算覆盖。真实复现：新局喝酒后284/134；随后学习林西吐纳术变200/102；独立新局喝酒后升2级变203/98。后两者已丢失酒的100/50加成。
- 修复时应采用可保存的永久增量/来源记录，让升级、心法、换装、读档不会重复发放或抹掉奖励；旧存档若没有可靠消费证据，不能仅凭当前上限推算并盲目补偿。
- 二式的兵器限制也需统一：当前资源没有一式的剑类限制。检查“已学/能用/能装备”的完整入口，不能把内部单个允许使用函数当作玩家可以使用未学技能的证据。

### 2.5 现有模拟器不足以证明实战平衡

`game/scripts/domain/combat_balance_simulator.gd` 已复用真实 `BattleFormula`，这是可继续利用的基础。但其装备按等级手填、每轮无限重复指定招式、敌人攻击技能近似等权；没有实际内力收支、完整AI决策、状态、治疗、补给和编队行动数。它能发现粗略伤害问题，不能验收真实开局或多场连续探索。不要仅改测试阈值让它变绿。

## 3. 外部方法与开源参考

以下为2026-09-10读取的一手资料；借鉴用途为本次分析，不表示直接移植其全部规则。

1. **Ian Schreiber：Numeric Relationships。** 数字应相对于生命、遭遇次数、金钱与成长比较；攻击提升也能通过更早击倒敌人减少承伤。用于把我们的平衡单位改成“行动次数、净生命损耗、连续探索能力”。[课程原文](https://gamebalanceconcepts.wordpress.com/2010/07/14/level-2-numeric-relationships/)
2. **Ian Schreiber：Cost Curves。** 成本不仅是金钱/法力，还包括限制与一次行动承载多个效果的价值；曲线形状服务于预期节奏。用于给固定伤害、攻击系数、控制、群攻、护体和回复建立统一预算，不仅按品质乘倍数。[课程原文](https://gamebalanceconcepts.wordpress.com/2010/07/21/level-3-transitive-mechanics-and-cost-curves/)
3. **FLARE。** 已读取引擎 `Entity.cpp`：护甲吸收受配置的比例上下限约束，伤害与减伤按阶段结算；官方属性文档分别定义内力消耗、资源要求与冷却。可借鉴可调减伤上限、资源成本与可审计分阶段公式。它是动作RPG，不能照搬其每秒输出或技能冷却到我们的回合制。[引擎仓库](https://github.com/flareteam/flare-engine) · [实际伤害源码](https://github.com/flareteam/flare-engine/blob/master/src/Entity.cpp) · [属性文档](https://github.com/flareteam/flare-engine/wiki/Attribute-Reference)
4. **The Battle for Wesnoth。** 官方区分地形相关的命中回避与伤害类型抗性，克制能使单位强弱随情境改变。可借鉴“不同招式有不同适用目标”，给破甲、控制和内外功真实价值；不照搬其高随机命中、六角地形体系。[开源工程](https://github.com/wesnoth/wesnoth) · [防御与抗性说明](https://wiki.wesnoth.org/Defense_and_resistance)
5. **GDQuest Godot Open RPG。** 当前官方README标为Godot4回合制教学项目、仍在开发中。适合参考战斗/资源组织，不应当作已调优完整商业游戏或现成数值答案。本轮仅核查项目定位，未完成其战斗源码审读。[项目](https://github.com/gdquest-demos/godot-open-rpg)

本轮没有下载整库、引入第三方代码或资源，也没有修改共享仓库。

## 4. 建议的第一版体验目标

基准是按正常路线取得的装备和技能，不强制稀有掉落、隐藏紫装或高手队友。指标针对整场敌人组合，不把每个敌人的目标伤害简单相加导致群战爆表。

| 战斗职责 | 参考完成回合 | 希望玩家感受到什么 |
|---|---:|---|
| 首场教学/陪练 | 2～3 | 攻击有反馈，能看出招式比普攻强；失误有代价但非致死切磋允许学习 |
| 初期普通战 | 3～4 | 不操作也许能胜，但用招式能明显省血、省时间 |
| 后续普通战 | 3～5 | 每个探索段有资源消耗，装备成型后旧敌人能1～2招解决 |
| 精英/可选高手 | 4～6 | 看懂重招、防御、控制或用药明显改善结果；准备不足有失败风险 |
| 章末Boss | 6～9 | 多一项成长或正确应对就能跨过难点，避免单纯加血拖时长 |

普通战以整场损失约10%～25%基准生命作为初步观察带；精英约25%～45%。这是测试用目标，不是按目标最大生命百分比扣血的运行公式。应分别报告净损耗、使用药物和最危险瞬间，防止治疗掩盖实际压力。Boss不设死板最终剩余生命，重点是胜率区间、可恢复失误次数和应对选择。

### 内力预算

- 普攻、防御保留0成本；林西一式先试4内力、二式先试8内力，配套保证足够的伤害提升；具体伤害值等公式与敌人预算确定后反推。
- 以84内力的初期主角为例，不计回复可用一式21次或二式10次，既不是免费无限放，也不是只能施展两三招。林西酒和吐纳带来的更大资源池应有稳定价值。
- 比较“全普攻”“节约用一式”“二式抢杀”“防御/治疗”四种策略。强招不要求每点内力效率最高，但必须在爆发、范围或控制上有不可替代作用。
- 检查每场后是否恢复、客栈/药物成本和路线补给，再校准3～5场连续探索的资源压力。若每场满蓝，单纯提高到4/8仍可能没有取舍；若完全无法补给，也会迫使玩家一直普攻。

### 防御公式实验

保留用户确认的“固定伤害 + 攻击系数”作为招式威力，不改成纯百分比。

- A：保留减法，但限制常规护甲最多吸收某比例的本次威力，搭配重设早期敌人攻击。这是FLARE式约束的思路，不代表使用它的具体常量。
- B：比较平滑减伤候选：`伤害 = 招式威力 × K / (K + 有效防御)`。K是全局或明确定义的预算常量，不能跟随玩家等级偷偷变大。比如仅用于演示的K=60、威力20、防御23时结果约14.5，不会突然从正常伤害掉到1；仍需重新校准敌人生命/攻击与全部装备。
- 两方案都只是在伤害阶段处理防御；命中失败、明确免疫与剧情机制必须独立定义。不同物理/内功、破防、暴击的顺序要固定且单测覆盖，不能一次攻击扣两次防御。

### 成长动力与开放世界

- 同阶段有代表性的装备/武学升级，应在固定基准敌人上看到约15%～30%的有效输出或生存提升，或跨过一次行动的击杀门槛；并非每件升级都必须达到该区间。
- 差异化来自暴击、先手、稳定攻击、防御、控制、破甲、回复与特定武学协同，不要求每一流派同时拥有所有优点。
- 提前取得紫装、高手同伴后碾压旧区域是正反馈，保留。更危险区域使用固定较高实力、组合机制和明确提示，不用章节锁或全地图自动追平玩家。
- 只对同阶段正常成长配置约束“不破防率”；终局角色回新手村挨1点伤害可以合理，不应以全局伤害下限毁掉防御成长。

## 5. 下一实施批次建议

1. **修正确性**：永久成长持久化、林西流派/兵器归属、四条战斗路径耗蓝一致、显示与实际加成一致；覆盖旧档迁移。
2. **建真实基准**：从真实角色/装备/心法资源组合生成裸装、正常路线、酒前后、强化装、提前紫装、高手同行、偏科流派样本。
3. **对比公式**：在上述样本和全章敌人/编队上跑A/B，不先批量覆盖数据；同时对比保留/取消全局残血衰减。
4. **第一章纵向切片**：先陪练→高阶弟子→山贼→凶兽→头狼→Boss，调整技能资源、怪物重招节奏、补给与奖励，实玩后再扩展后续章节。
5. **自动验收+人工体验**：固定多组随机种子，记录胜率、行动次数分位数、伤害为1比例、内力/药物消耗、先手差异、强装提升和异常叠加；保留失败样本。通用公式测试通过不能替代这一步。

当前边界：已核查公共公式、成长与装备加成链，已做第一章重点敌人矩阵及全敌人资源低伤害扫描；未完成全八章完整队伍AI、多场补给和每种武学配装的随机仿真，不能宣称“全数值已平衡”。
