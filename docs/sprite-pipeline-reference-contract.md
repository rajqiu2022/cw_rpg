# 素材板与精灵制作参考合同

本次为洛阳素材管理试点：借鉴参考板、素材索引和整条动画共同制作的工作方式，由本工程独立实现。没有抽取第三方源码、复制上游提示词或接入付费服务；未修改正式地图、存档与生成任务。

## 索引和状态

`assets/catalog/luoyang-assets.json` 登记 20 个真实文件。`luoyang-board.json` 保存默认最多五个共享参考 ID 与可编辑中文 brief；导出只产生参考清单，不提交任务。`sprite-contracts.json` 记录当前源码及处理器可核实的合同。

- `adopted`：当前 canonical 场景→layout→PNG，或场景 NPC→NPC catalog→头像的引用已定位。仅表示现役消费，不表示艺术验收全部通过。
- `candidate`：已有产物、尚未证明正式角色或敌人绑定。
- `reference`：材质来源或历史对照，不自动参与运行时替换。

目录名中的 `candidate`、`proposal` 或旧报告的未采用状态都不能单独判断现在是否现役；以当前 canonical 消费链为准。反过来，入 `game/art` 目录也不等于采用。

许可证与使用状态分开。项目生成/原创或派生素材不是 CC0；底层来源不明确时保留未知。Poly Haven 本地 manifest 的 CC0 只覆盖所列源资产，不能将整个混合建筑/场景冠以 CC0。商用条款还需单独核查。

## 新精灵的最小制作流程

1. 先选择合同：场景主角、场景 NPC、人体战斗或具体动物，不能混用画布/高度/帧数。
2. 固定身份、镜头、朝向、灯光和尺寸；同一动作序列共享认可参考。人体战斗为五状态各四帧，优先一个 4×5 atlas 保持身份。场景方向缺图宁可报缺，不无参考补造。
3. 保存 raw、真实生成 meta、task ID 与成本；依赖参考的任务先 dry-run，参考丢失拒生成。本试点不创建任务，也不开启 API。
4. 用本项目既有处理器去背景和拆帧。所有状态共用一个比例，固定画布、中心和脚底；不对每帧分别 fit。人类与动物不能共用人体站高标准。
5. 保存 processed、预览及 QA 报告，检查脚底、尺度、方向、身份连续和动作相位。数值通过不取代肉眼审查；loop-check 多出来的复制帧不导入正式动画。
6. ART 交给 SYSTEM 绑定后再做 Godot 最小验证，才记录现役引用。不能仅因文件存在或目录名更新状态。

## 当前可核合同与历史差异

现役 Player 源码使用 v7 武器变体，160×160 cell，idle 四帧、walk 八帧，底边 8px；不能沿旧 sprite 手记 MVP 上下四帧推荐认作当前运行合同。NPC 则按 strip 宽高检测 hframes，脚底采用真实首 cell 非零 alpha bounds，不能未经测量沿用主角的 8px。

人体战斗沿 `docs/battle-sprite-standard-v2.md`：512×384、底边 12px、普通站高 300px、boss 至多 330px、己方朝右/敌方朝左。虎候选使用自己的 ready 目标 460×265 和同二十帧统一比例；这不是“虎身高 300px”，也不表示已接入敌人。

## 本板暂缺

小民房、大民房、富家豪宅、独立园林花草与室内套件未在本次登记到可靠的当前洛阳消费链。商铺和组合街面不能冒作这些新类型；下一步先补真实素材与记录，再决定生成/摆放。墙门亮度断层、水岸直线和城区丰富度等原待办不因索引上线而消失。

已完成：20素材真实索引、默认五图共享参考配置、四种合同的本地来源整理；管理工具的页面预览/选参考/导出与缺失检查已完成关键验收（NodeQA 30/0，主控浏览器实际六图导出包通过）。

待办：补齐民房/豪宅/园林花草/室内素材与来源，图像风格、后续生成和正式布局另行验收；管理工具通过不授 Godot 遮挡、Physics、动画接入或商业许可信用。
