# 场景美术质量标准与批量复查流程

版本：2026-11-01。适用于本项目可行走室内、城镇、门派、野外及 World 地标。用于把反复出现的用户否决转成制作前置条件；不是对现有地图的新一轮验收，也不授权修改全部场景。

配套：[缺陷登记册](scene-art-defect-register.md)。本规范补充而不替代 [AI 硬规则](ai-rules.md)、[UI 规范](ui-style-guide.md)和模块写权。新素材生成、原图处理、正式接线仍须遵守既有授权。

## 1. 先确定交付对象，再开始摆件

开工单必须给出：实际 scene ID / 入口、现役作者或布局路径、场景用途、主要玩家动线、这批改变什么及保留什么。不得只写“优化地图”“更丰富”。

先完成下面四项，再决定素材复用/补图：

1. 空间身份：此处是什么地方、为什么在这里、与邻区怎样连接。豪宅要有独立门庭/院落关系，接待厅要读得出接待与会客；不是给通用客栈改标题。
2. 用途分区：入口、主要活动区、服务/后台、生活区怎样相邻；家具、居民与业务服务这些用途，不以随机摆件数量充完成度。
3. 结构与动线：主次道路、连续街沿/院界、台地与桥阶、可进入门及封闭边；先解决拓扑和建筑支撑，不先堆装饰补空。
4. 视觉主次：正常镜头首先看到的地标和活动区是什么。地域差异靠空间组织、建筑类型/层数/朝向、材质和用途表达，不是同一十字街换色。

大改沿“总规 → 有成人标尺的局部平面/接口 → 完整建筑与地面 → 人物与生活 → 正常镜头复查”。已有用户确认的总规须列出实际偏离，不把透视概念图当足迹或导航真值。局部修门/收边无需再造整城总规。

依据：[汴州设计前置教训](experience-log.md)（2026-10-22汴州用户纠正）、[岚溪重排与真实台地历史](changes/miao-recompose-20261029g.md)、[岚溪三级台地](changes/miao-terrain-20261029i.md)。

## 2. 硬准则：必须在实现前可回答、实现后可核对

### S01 成人、净门与家具共用尺度

- 本项目当前近场参考为主角可见站高约 **128px**，已核林西样本为128.52px；普通成人参考族120–132px。量人体头到落脚，不量透明画布、长枪/帽饰的最外包络，也不把所有儿童、老人、坐姿强拉成128px。
- 记录具体方向/帧、源图、sprite等比倍率、原脚锚与正常相机zoom。相同画布不等于相同人体；同人待机、行走、对白切换不能忽大忽小或漂脚。
- 可进入门必须量**净开口**，不是整张门楼、两柱中心距或台基宽。以同画面成人作尺，门高须足以呈现正常成年通行，不靠截头、压人或透明横梁过关。林西30h已接受门高145.7–152.5px可作同相机近场建筑的起始参照；不同透视/门型须另测，不能机械套所有门。
- 门宽和门前通行须容纳当前真实完整脚体及交互站位；碰撞净宽与头部可见是两项。矮储藏舱、装饰窗须明确不可通行，不能用它冒正式入口。
- 层高、栏高、桌椅与人一起定标。多层楼按实际层数建立体量，不将两层楼整栋压到约三个人高；不得为挤进街宽而缩成人或把院墙变膝高玩具。

参考：[林西成人/门高实据](changes/linxi-adult-building-scale-20261030h.md)。World是另一微缩层级，不拿World城廓与近场成人作同一标尺，但各地标在World内部须有一致层级。

### S02 完整形体、原生比例与像素预算

- 建筑、山石和陈设保持完整可信轮廓、原生宽高比例及相机方向；正面墙旋转不等于有纵深的侧墙。完整图等比缩放也不自动合格：成人门变玩具、石纹变巨块仍拒绝。
- 先登记“源主体有效像素 → 世界可见大小 → zoom/窗口stretch”的关系。近场不得把微缩城图、低清整圈墙或薄岩面巨幅放大冒高清建筑/山崖；优先原生短段、匹配方向的组件或重新规划占地。
- 不把横向岩面UV压到近竖直边上，不能以纸片墙、拉长岩柱、排队L岩冒自然山势。真实高差须有台面、连续边界、必经阶口及同源的角色/物理层级，不能在平地散放楼梯。
- 接段要读成一体：不得留下断列山石、悬空楼脚、穿楼后墙或镜像接缝。允许有依据的整段复用/镜像，但不能用“等比”“RGBA同”反驳正常画面中的重复和模糊。
- 背景远山可采用等比cover等适合其用途的方案；不把近场一律scale≤1当唯一门禁，也不以远山的例外授权近场放大。

参考：[赤岩/沙漠像素返工诊断](changes/desert-city-pixel-rework-20261029n.md)、[岚溪薄片坡岸](changes/lanxi-occlusion-and-banks-20261030l.md)、[华山首版偏差](changes/huashan-map-20261029m.md)。

### S03 地面材质、相位与边界

- 连续道路/院地先合轮廓，再贴同一worldUV或等效连续坐标；不能每段重启相位、十字口重复叠暗，不能把Line2D平铺参数当已开启正确纹理重复的证据。
- 材质粒度须在成人脚边正常镜头看：土、碎石、砖缝、田垄不能像巨块地毯或等宽深褐管路。道路层级应清楚，支路/生活路不要处处官道宽。
- 草土、砂土等自然过渡要有可信路肩、宽度变化与接地；硬边仅用于真实铺装/台基/院界，不把矩形材质岛硬贴在草上。软化不得涂掉桥口、门槛或道路真实结构。
- 台基接地、桥岸接街、墙角铺地不能露草缝、黑灰底或未铺边。shader、UV和铺底按实际正常镜头覆盖验收；视觉补底不扩大可走区。
- 新底材/铺石/路边的排序必须计算祖先`z_is_relative`后的**有效深度**，不能只比较各自local z；绝对底层与相对铺石混用可让底材盖掉全片道路。深度断言与实际正常图须同时成立，参见11-01b的95060反例及44444后继。
- mini读取同源地形/静态建筑及正式坐标，不能在mini另画一套看似正确的路；简框按现役UI规范，不降低地图和marker本体透明度。

参考：[岸驿地面11-01a](changes/riverside-visual-20261101a.md)、[会客厅shader/露底](changes/luoyang-hall-enclosure-20261029p.md)、[城内实景mini](changes/city-visual-minimap-20261030c.md)。

### S04 建筑围合、门、桥与真实路线一致

- 院墙/城墙必须有可理解的封闭边界和正式开口；孤立短墙不为“丰富”而摆。门洞、门柱/台基、箭头、实际热区、入口/返回脚须属于同一可达关系。
- 楼梯踏面不是遮挡前景；桥柱/栏顶不是可走floor。门前能站一点不等于整段通路成立：检查从公共路接近、完整脚体通过、门后落点和走离空间。
- 新楼和低家具还要避开原NPC完整巡路、任务接近/末腿及门返脚，不能只查NPC静止点；图、实体、NAV、安全几何和实际构造消费者要同步。
- 海岛/海峡必须在真实NAV上隔断陆路，不能只盖海水色；桥后城前空间须在正常画面中有引道/前坪，而非桥头顶城门。地理改动同时更新M/mini与受影响返回锚点。
- 原来就不开放的水岸/侧路不因测试方便删除阻挡。新增实体覆盖旧合法脚时，按现役兼容合同定向迁移；不以任意nearest掩盖错误门户。

参考：[离岸岛与城前空间](changes/world-coast-island-implementation-20261031h.md)、[宅院门槛](changes/luoyang-hall-threshold-20261029o.md)、[街坊巡路/任务末腿](changes/city-neighborhoods-and-mountain-finish-20261031d.md)。

### S05 人物姿态、方向与内容诚实

- “坐客”必须有真实坐姿：臀部落座、腿脚姿态、椅背/桌面前后关系可信；不能将站立精灵下移、用桌子遮腿或缩小一半称坐姿。没有合格坐姿时明确资源缺口，可改为合理站位，不宣称已坐下。
- **方向帧不是时间动画**。有真实坐姿的四方向strip，也不得按帧索引轮播造成约一秒内左/下/右来回转身。闲坐默认固定合理朝向；只有同一方向真实呼吸/喝茶动作才能作idle循环，明确的交谈转向另有触发。复查至少观察完整一轮实际循环，不凭单张截图判断动态已修。
- 方向按源帧与实际运动核对，不信文件名right；换向核flip约定、脚锚和身份。静态帧不同不等于真实步态，重复宽跨不能冒四/八相位行走；镜像方向和未制作方向须明示。
- 帧内不能裁脚、裁头、截武器；增加透明留白不能修复原来缺失的主体。可用合格完整现货替换，但年龄、职业、服饰和同人头像须相符。
- NPC职业/对白须有画面支持。无乐器/演奏姿态不能称现场乐师；普通掌事不能乱配另一人肖像。姿态检查不能仅凭NPC名称或数据标签通过。

参考：[怡红院历史局部边界](changes/luoyang-yihongyuan-20261029n.md)、[实际商贩方向](changes/world-sects-cities-repair-20261031c.md)、[人物源帧教训](experience-log.md)（2026-10-29a、2026-10-19ad）。本次用户图中两人有坐姿，当前问题是快速来回转向，不能误诊为缺坐姿而无关重生人物；旧“两名闲坐客人”也不能证明动画语义正确。

### S06 遮挡保护空间，不能挖建筑救人物

- 建筑/屋顶保持不透明；当前独立前景方案以同一角色纹理、帧、flip、脚锚/变换在前景上方显示半透明影像，既有采用值alpha .42可继承，不擅改全局策略。
- 判断真实前景alpha和有效父层深度；不要把透明画布当遮挡，不只比较局部z或visible属性。Polygon铺街与Sprite同样要覆盖，NPC不能只剩腿。
- 门洞横梁、桥阶和柜台前后分层须可信；不能抬高整个人物z穿过屋顶，也不能用整栋透明洞补错误排序。
- 烘焙底图的既有特定淡化合同与独立前景影像是不同策略，不得不看消费者就批量替换。最终必须在正常画面看到玩家、需要交互的NPC及门前通路。

参考：[岚溪建筑不透明](changes/lanxi-occlusion-and-banks-20261030l.md)、[World有效父层问题](changes/city-neighborhoods-and-mountain-finish-20261031d.md)。

### S07 正常镜头是最后的视觉否决点

- 以现役场景的原zoom、跟随/单屏规则、窗口尺寸和HUD看画面，先核首入场完整人物/箭头可见；不能硬写zoom1或抬镜头让问题出框。
- 同一问题保留前后同位置、同方向/帧、同镜头的可比较正常图；小范围修复通常一张关键点图足够，围合/整体布局才补一个必要第二视角或总览。
- 总览可看拓扑/密度，不替正常镜头的门高、石纹、姿态、遮挡。传送/公开near截图不得说成连续走到；源码/来源/物理PASS不得说成画面好看。
- 正常图已明显被拒时，登记具体对象与标准号；先改原因，再检查残余。不要继续加断言、换视角或复跑旧成功矩阵来证明“完成”。

## 3. 可复用批量流程：一轮基线、按原因成组、只复查变化

1. **列范围**：按实际注册scene ID建立本批清单，区分正式现役、草案、历史被拒、非本批。每场景关联入口/来源/现有证据与S01–S07适用项。不要把扫描到的所有文件算成已审场景。
2. **只读基线**：优先读当前作者/布局及现有正常图，记现役来源身份；旧图须标历史，缺图写未核。沿真实消费者定位问题，不先全工程导入或启动长矩阵。
3. **原因分组**：把“地面管路/UV重启”“玩具门/画布量尺”“假坐姿”“薄片崖”“通用房改名”等分别成组，查同一helper/素材/制作方法的其他实际消费者。共享原因的修复只在授权范围内，不能顺手改所有城。
4. **先接口样板**：涉及新建筑类型、山崖/地面方法时，先用成人+净门+接地/接段的一个正常镜头样板。样板不合格不全城复制；已合格组件不跟失败组件一起重生。
5. **有限实施**：按模块写权和授权计划做一批连续可见空间，视觉/实体/业务受影响关系一次查清。不动无关存档/进程、不放宽来源或通行校验。
6. **按风险验证**：纯视觉改动核新资源/变换与关键正常图；改实体补受影响短路/阻挡负例；改门补一次真实进返；改高程补受影响阶口；改地理补真实连通域与必要旅行。不机械要求每批全城/全部旧门/战斗/制作/长连续游历。
7. **结论与停止**：填写下方记录和缺陷登记册，只关闭有对应证据的缺陷。成功组件继承已有结果，后继只跑失败残余；交试玩时列仍待用户判断项，不能用“局部通过”漂白整图。

本规范不新增微秒级性能门槛、通用浮点精度标准或固定检查数量。性能/精序列化按具体功能合同验证，避免把艺术复查扩大成无关技术工程。

## 4. 结论必须分层

| 维度 | 可以写什么 | 不能推导什么 |
| --- | --- | --- |
| 来源/资源 | 已核实际资源、身份和有限导入 | 不推出尺度、风格或用途合格 |
| 功能 | 指明入口/短路/脚体及真实输入范围 | 不推出全城、全路线或真实读盘已测 |
| 视觉 | 正常图具体通过/拒绝的S项与对象 | 不推出未看区域、其他场景或全ART |
| 设计身份 | 总规/用途/地域关系的符合与偏离 | 摆件数量、NPC数量不能代替 |
| 用户接受 | 明确哪次用户反馈、哪张图、哪一范围 | AI旧“亲看通过”不覆盖用户后续否决 |

“历史局部已修”与“当前新投诉待复核”可以同时存在。新投诉不得写成旧问题一直没修，也不能拿旧通过断言当前无问题。缺证据填“未核”，不填“默认合格”。

## 5. 一页复查记录模板

复制到本批工作目录或变更记录；一场景/一原因组一条即可，不强制建立新工具链。

```text
场景 ID / 正式入口：
当前作者/布局/消费者路径及身份：
本批范围 / 禁改范围：
用途一句话 / 主路—活动区—后台或生活区关系：
既有证据（历史日期、路径、范围）：
本次用户反馈/待核项（标准号、对象、可观察症状）：
成人参考帧 / 可见身高 / 门净开口 / 世界倍率 / zoom：
关键物件原生比例 / 地面UV和粒度 / 姿态与真实方向：
受影响路、门返脚、巡路、遮挡消费者（无则写无）：
前图 / 后图（正常镜头条件；无图写缺失）：
本次实际检查 / 继承哪些旧成功 / 保留哪些FAIL：
结论分别填：来源、功能、视觉、设计身份、用户接受：
剩余缺陷 ID / 下一责任域 / 停止点：
```

快速复查只需逐项回答：身份先成立了吗？成人/门/家具同尺吗？完整形体与接地合理吗？地面连续且粒度正确吗？姿态/朝向真实吗？围合/门路/遮挡与画面一致吗？当前正常镜头证据支持到哪一步？
