## 史料与游戏取舍

本作是架空大乾，不是某朝洛阳的考古复原。参考隋唐的街坊、水系和城防骨架，以及唐宋之际更开放的街巷生活；不得将不同时期细节混合后称作准确复原。

- [霍宏伟《隋唐洛阳城空间体系研究》介绍，全国哲学社会科学工作办公室](https://www.nopss.gov.cn/n1/2024/0904/c458483-40313012.html)：城、苑等空间的联系，以及封闭里坊向开放街巷的变化。转化为游戏设计：城区必须有功能分区和连续街巷，而不是孤立建筑散布在同一大广场。
- [故宫所刊里坊复原图](https://www.dpm.org.cn/Uploads/File/2021/01/20/u6007f09329708.pdf)：检索摘要显示城门、街坊、水系、桥梁的位置关联；正文抓取超时，仅作待补读的图示参考，不据此指定精确历史尺寸。
- [林嵩《洛阳名园记》与古典园林的唐宋变革，北京大学](https://jypl.pku.edu.cn/Article/info?aid=330803339)：都市园林强调人工与自然协调。转化为游戏设计：豪宅有围合园林，公共绿地有亭池和曲径，不把花草平均撒在整张石地面。

## 加载诊断与修改边界

现有 LoadingManager 已调用 `load_threaded_request`，但只读通用 Field PackedScene。地图路径是 SceneScript 字符串，重校验/PNG解码/导航栅格/物件初始化仍同步；Router 在 Loading 展示之前已经解析城市，同次转场还重复解析。Field 对象创建结束没有明确握手，Loading 只等一帧即隐藏。

实施顺序：

1. 真正入口先展示 Loading、给一帧绘制机会，再准备资源；已有同步 bool 返回 API 不暗改为异步返回。
2. ResourceLoader 后台读取目标资源；世界只预读首屏区块，不预读全64块。进度区分读取、验证、布置，不在资源读取完成时虚报100%。
3. 主线程按时间预算分批建立Sprite/碰撞/NPC；几何完成后才出生玩家、解除输入，Loading 等实际ready握手再退出。
4. 同次 transition 的完整验证结果按独立token传递，杜绝重复执行；失败/取消清理，禁止跨场永久跳校验。
5. 仍慢的PNG/导航/纯文件哈希阶段需另做可安全worker的拆分；不能后台操作SceneTree、Physics或RenderingServer，不能只加Loading掩盖首次28秒主线程阻塞。
